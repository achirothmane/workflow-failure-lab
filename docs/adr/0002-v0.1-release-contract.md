# ADR-0002: v0.1 Release Boundary and Verification Gates

- Status: Accepted
- Date: 2026-07-19
- Deciders: Project owner (scope origin), principal engineer (recording only)

## Context

Work items B1 through B5 are complete:

- B1 — implementation plan and ADR-0001 (`docs/implementation-plan.md`, `docs/adr/0001-scope-and-vocabulary.md`).
- B2 — first vertical slice: execution log to incident report, including the JSON Schema in the parsing module.
- B3 — example corpus and fail-closed retry policy tests.
- B4 — CLI contract, README, Makefile, and CI.
- B5 — dependency-direction and no-cycle enforcement tests, discharging the "test in B-later" deferral of implementation plan §3.

Together, B1–B5 complete the v0.1 functional scope. This ADR records the release boundary for v0.1 and the gates that must pass before tagging `v0.1.0`. It extends no scope: it freezes what already exists.

[ADR-0001](0001-scope-and-vocabulary.md) remains binding and unmodified. Its vocabulary and rules are referenced here, never restated or re-derived; its observed gaps remain owner-gated proposals, untouched by this ADR.

## Decision

### Frozen v0.1 product contract

The following contract is frozen for v0.1. It records the behavior already implemented and tested at the time of this ADR; nothing in it is new.

1. **Input** — one local JSON file containing one execution and its steps, validated against the JSON Schema that lives with the parsing module. No other input source.
2. **Output** — one deterministic Markdown incident report printed to stdout: identical input produces identical output (no wall-clock timestamps, no randomness).
3. **Vocabulary** — exactly the three certainty terms fixed by ADR-0001: `SUCCEEDED`, `FAILED_CONFIRMED`, `INDETERMINATE`. No additions, renames, or synonyms.
4. **Retry/reconciliation guidance** — exactly ADR-0001's two binding rules (retry rule and reconciliation rule), applied as advisory output only.
5. **CLI command** — `python -m workflow_failure_lab report <path>`.
6. **Exit codes** — as documented in the README: 0 (report produced; classification never affects the exit code), 1 (internal error), 2 (usage error), 3 (invalid input).

Changing any part of this frozen contract requires a superseding ADR approved by the project owner.

### v0.1 non-goals

Version 0.1 ships without:

- network calls;
- a database or any persistence;
- automatic workflow execution or retry — the tool advises, it never acts;
- external reconciliation execution — the tool states that reconciliation is required, it never performs it;
- a web UI or service;
- new domain vocabulary.

### Release verification gates

Tagging `v0.1.0` requires all of the following, in a checkout of the release commit:

1. Clean working tree (no uncommitted or untracked changes).
2. The complete `pytest` suite passes. The requirement is the complete suite, deliberately not a fixed test count.
3. The CLI contract tests pass (`tests/test_cli.py`).
4. The dependency-direction and no-cycle tests pass (`tests/test_dependency_direction.py`).
5. Deterministic example output: repeated runs of the CLI on the example corpus produce byte-identical reports.
6. `git diff --check` reports nothing.
7. Clean-package installation and CLI smoke verification: the package installs into a fresh environment and the CLI command produces a report there. This gate is required before tagging; its implementation and execution are B7 (below).

Gates 3 and 4 are subsets of gate 2; they are named separately because they verify the frozen contract and the architecture rules directly, and must not be skipped or deselected.

### B6 / B7 boundary

- **B6** is this accepted release-contract ADR. It is documentation only: no production behavior, test, dependency, schema field, or domain rule changes.
- **B7** is the implementation and execution of the clean-package release verification gate (gate 7). B7 is named here but not designed here.

## Consequences

- The v0.1 product contract above is frozen; any change to it requires a superseding ADR approved by the project owner.
- ADR-0001 is unaffected: its vocabulary, binding rules, and open proposals stand exactly as written.
- Release readiness for `v0.1.0` is now a checklist, not a judgment call: all seven gates must pass, and gate 7 blocks tagging until B7 has run it.
- Any perceived need to extend v0.1 scope before release is a new decision, not an amendment to this record.
